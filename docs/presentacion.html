🏗️ Arquitectura Limpia (Clean Architecture)

Dividir el código en capas desacopladas es el secreto para que las pruebas sean rápidas y no requieran emuladores:

1. Dominio (Domain)

Casos de Uso y Modelos puros en Kotlin. Cero dependencias de Android. Se prueba en la JVM en milisegundos.

2. Presentación (UI)

Jetpack Compose y ViewModels. Maneja el estado reactivo (StateFlow) y responde a eventos del usuario.

📦 Gestión de Dependencias Moderna

En lugar de versiones dispersas en archivos Gradle, usamos Version Catalog (gradle/libs.versions.toml):

# 1. Definimos la versión en un solo lugar
[versions]
junit = "4.13.2"
turbine = "1.2.0"

# 2. Registramos el artefacto
[libraries]
junit = { group = "junit", name = "junit", version.ref = "junit" }
turbine = { group = "app.cash.turbine", name = "turbine", version.ref = "turbine" }

🔐 ¿Por qué firmamos las aplicaciones?

Identidad & No Repudio

Demuestra criptográficamente que la app fue creada por ti y no por un impostor.

Integridad del Binario

Garantiza que el APK no fue alterado o inyectado con código malicioso tras compilar.

⚠️ Regla del SO Android: No se puede actualizar una app instalada a menos que el nuevo APK esté firmado exactamente con la misma clave.

🔑 El Keystore y las Huellas SHA-256

El almacén de claves (.keystore) protege el par de claves RSA:

# Comando para generar un almacén PKCS12
keytool -genkeypair -v -keystore release.keystore \
    -alias todoapp_key -keyalg RSA -keysize 2048 \
    -validity 10000 -storetype PKCS12

La huella SHA-256 es el identificador público que vinculas en Firebase Console y Google Cloud.
